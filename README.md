# Coin Agents Office

AI 에이전트 팀이 협업해서 **크립토 무기한 선물(perp) 매매 전략을 발굴 → 백테스트 → 리스크 필터링 → 리포팅 → 실매매**까지 수행하는 개인용 자동매매 시스템입니다. 역할이 나뉜 7명의 에이전트가 사이클마다 데이터 수집부터 발주까지 릴레이로 처리하며, 웹 UI에서 각 에이전트의 작업 현황·로그·리더보드·포트폴리오를 실시간으로 볼 수 있습니다.

**세 가지 실행 형태**

| 형태 | 용도 | 키 필요 |
|---|---|---|
| **웹 서버** (기본) | 페이퍼 → 실거래 전환 가능 | 실거래만 필요 |
| **데스크탑 앱** (`desktop/`) | 모의거래 전용, 비개발자 배포용 | 불필요 |
| 백테스트/연구 | 전략 탐색·검증 | 불필요 |

Binance 공개 API 기반이라 페이퍼 모드는 **키 0개로 동작**하고, LLM·유료 API 의존이 없습니다.

## 매매 규칙이 코드로 강제됩니다

`docs/trading-rules.md`가 규범(normative) 문서이며, **RiskEngine**(순수 함수 게이트)과 **TradePlan**(시나리오 자료구조)이 이를 강제합니다:

| 규칙 | 강제 지점 |
|---|---|
| 레버리지 BTC ≤10x, 그 외 ≤5x, 최소 3x | RiskEngine 정적 게이트 |
| 격리(Isolated) 마진 고정 | 브로커가 진입 전 설정 |
| 지정가만 (진입·익절 = post-only maker) | Broker ABC — market 주문 경로 없음 |
| 분할 진입 50/25/25 · 분할 익절 (레그 합 = 100%) | TradePlan 구조 검증 |
| 손익비 미달 진입 금지 (BTC·ETH 1:2, 알트 1:3) | side-aware RR 게이트 |
| **최소 손절 거리** (가중 진입가 대비 0.5% 이상) | RiskEngine — 진입가·손절선 근접 플랜 차단 |
| 진입 근거 2개 이상, 시나리오 없는 주문 거부 | evidence 검증 + **브로커 레벨** 플랜 게이트 |
| CPI·FOMC 블랙아웃 (±12h) | econ_events 런타임 게이트 (TTL 재큐에도 적용) |
| 손절 = 4h 종가 판정, 손절 미루기 금지 | PositionMonitor + 유리한 방향만 수정 허용 |
| 복리 금지 (시드 고정, 수익 출금) | 사이징 게이트 `min(잔고, 시드)` + withdrawal_ledger |
| 저시총 금지 | 유니버스 화이트리스트 (BTC/ETH/SOL/XRP/DOGE/ADA/LTC) |

손절/청산회피 청산만 예외적으로 taker(공격적 reduce-only 지정가)를 허용하며 백테스트도 동일 비용(0.05%)으로 모델링합니다.

### 복리 금지의 구현 (2단 구조)

1. **사이징 게이트** — 플랜 마진은 항상 `min(지갑, 시드) ÷ 최대 동시 포지션`. 수익이 나도 매매 규모가 커지지 않습니다.
2. **출금 스윕** — 시드 초과 실현 수익을 UTC 일 1회 `withdrawal_ledger`로 격리. 페이퍼는 지갑에서 실제 차감, **라이브는 장부상 격리만**(거래소 잔고 무접촉, 출금 API 미사용 — API 키에 출금 권한을 주지 않아도 됨). 이미 격리한 누적액을 차감해 이중계상하지 않습니다.

UI 포트폴리오 탭에서 **총 자산 / 매매 가용 자금(=시드) / 누적 출금 / 누적 실현 손익(승·패)** 을 한눈에 봅니다.

## 시장 레짐 판정 (모든 전략의 상위 필터)

규칙 §4-3(TOTAL2/3 + 도미넌스)을 Binance 일봉으로 계산하는 **키 프리 프록시**로 구현했습니다 (TradingView TOTAL2는 무료로 과거 데이터를 못 받아 백테스트가 불가능하기 때문).

- **알트 지수** = BTC 제외 유니버스 종가의 등가중 정규화 지수 (TOTAL2/3 대용)
- **도미넌스 프록시** = BTC 종가 ÷ 알트 지수

각각 50일선/200일선을 비교해 4분면으로 판정합니다:

| 시장(알트지수) | 도미넌스 | 레짐 | 매매 |
|---|---|---|---|
| 상승 | 하락 | `long_alt` | 알트 롱 |
| 상승 | 상승 | `long_btc` | BTC 위주 롱 |
| 하락 | 상승 | `short` | 숏 |
| 하락 | 하락 | `cash` | 관망 (시장 이탈) |

히스토리 200일 미만이면 `cash`(진입 차단). 하루 1회 완결 일봉으로만 판정하고, 인트라데이에서는 **전날 확정값만** 읽습니다(룩어헤드 차단). 롱 전략은 롱 레짐에서만, 숏은 숏 레짐에서만 플랜을 냅니다.

## 전략 템플릿 6종

모든 전략은 시그널이 아니라 **완성된 시나리오(TradePlan)** 를 출력합니다 — 진입 근거 2개 이상 + 분할 진입 50/25/25(패시브 지정가 3단) + 손절선(시나리오 붕괴 지점, 4h 종가 판정) + 분할 익절 2단. 익절 거리는 손절 거리의 R배수로 탐색(1차 2.2~4.0R, 2차 4.0~6.5R)되어 **가중 손익비가 구조적으로 1:3 이상**이며, 레버리지도 3~10 범위에서 탐색하되 심볼 캡에 잘립니다.

스윙 피벗·VPVR 등 모든 구조 지표는 **우측 k봉 마감 후 확정된 값만** 사용하며, 룩어헤드는 TF별·지표별 오염 테스트로 회귀 방지됩니다.

### 1. `topdown_pullback` — 톱다운 눌림목 (기본기)
일봉 200선 위 확인 → 4h 골든크로스(fast 30~70선 ↑ slow 120~240선) → 15m에서 fast선 눌림(±1~5% 밴드) + 거래량 확인(평균의 1.0~2.5배) 후 지지 레벨에 분할 래더. "큰 흐름 읽고 작게 들어간다".

### 2. `ma_confluence` — 이평선 황금타점
4h 50·100·200선이 한 지점에 수렴(허용 오차 0.4~3%)하는 자리에서 지지 시 눌림목 매수, 손절은 수렴 지점 바로 아래(0.5~3% 패드) — "지지되면 눌림목, 이탈하면 칼손절". 패닉 급락(8~30%) 시 400선 분할 매수 분기 포함.

### 3. `box_range` — 박스권 매매
4h 확정 피벗으로 박스를 긋고 **하단 15~30% 구간에서만 롱, 상단에서만 숏** — 중간(손익비 1:1 홀짝 자리)은 관망. 손절은 박스 이탈(높이의 2~10% 버퍼), 익절은 1차 부분 → **최종 미드포인트**(반대편 끝까지 기다리지 않음).

### 4. `vwma_support` — VWMA·VPVR 보조 판단
VWMA 60~150선(기본 100선) 위 지지 확인 후 조정 시 그 선까지 기다렸다 매수. VPVR(80~200봉 거래량 프로파일) 매물대를 손절·익절 기준선으로 사용. VWMA+VPVR 동시 하향 이탈 = 숏 플랜.

### 5. `candle_breakout` — 돌파 후 리테스트
장대양봉(몸통 평균의 1.5~3배)+거래량 폭발 돌파를 확인하되 **추격 금지** — 돌파 레벨 ±0.5~3% 밴드로 되돌아오는 눌림 리테스트를 기다렸다 패시브 진입. 저항대 윗꼬리 음봉 = 숏, 지지대 아래꼬리 양봉 = 롱 분기 포함.

### 6. `vpvr_accum` — VPVR 매집 (롱 전용)
상승 후 전고점 아래 타이트 횡보 구간에서 **거래량이 전고점이 아닌 횡보 밴드에 집중**되면 매집으로 판정, 전고점 재도전 롱 시나리오. 손절은 횡보 밴드 하단 이탈. 롱 전용이라 숏 레짐에서는 휴면 상태입니다.

**챔피언 선출** — 사이클마다 위 범위에서 랜덤/변이 샘플링(챔피언 파라미터 ±20% 변이 포함)으로 후보 60개를 만들고, 유니버스 × 멀티TF 백테스트 → 리스크 필터(청산 1회 = 즉시 탈락, MDD·최소 거래수·활동성) → 가중 랭킹(샤프 35%·수익 30%·MDD 20%·승률 15%)으로 선출합니다. 목표 탐색 모드는 5사이클마다 walk-forward OOS 검증을 끼워 넣고, 챔피언이 롤링 드로다운 한도를 깨면 자동 강등됩니다.

| TF | 용도 |
|---|---|
| **1d** | 레짐 판단(알트지수·도미넌스 50/200선), 톱다운 200선 필터 |

## 설치 · 실행

요구사항: Python 3.12+ / Node.js 18+

```bash
# 백엔드
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 프론트엔드 빌드
cd ../frontend
npm install && npm run build

# 실행 (단일 포트)
cd ../backend
.venv/bin/python -m uvicorn app.main:app --port 8000
```

`http://localhost:8000` 접속 — API·WebSocket·프론트가 한 포트로 서빙됩니다. 첫 실행 후 **🔬 전략 연구**를 한 번 돌려 챔피언을 만들어야 매매가 시작됩니다.

### 상시 운전 (macOS launchd 예시)

`~/Library/LaunchAgents/com.coinagent.server.plist`에 등록하면 죽어도 자동 재기동되고 로그인 시 자동 시작됩니다 (`KeepAlive`). 절전 진입 시에는 프로세스가 일시정지되므로 24시간 운전하려면 전원 연결 + 잠자기 방지가 필요합니다.

## 실전 매매 전환

기본은 **paper 모드**(초록 뱃지). 전환 조건: **키 설정 + flat-and-idle**(사이클 미실행·오픈 주문/포지션 0·활성 플랜 없음) — 아니면 409 거부.

```env
# backend/.env — Binance USDT-M
CA_BINANCE_API_KEY=...
CA_BINANCE_API_SECRET=...
CA_BINANCE_TESTNET=true          # 먼저 테스트넷으로 검증 권장

# 또는 OKX (키 3종: key + secret + passphrase)
CA_EXCHANGE=okx
CA_OKX_API_KEY=...
CA_OKX_API_SECRET=...
CA_OKX_API_PASSPHRASE=...
CA_OKX_DEMO=true                 # OKX 데모 트레이딩

# 자금 설정
CA_INITIAL_SEED_USDT=1900        # 고정 시드 (사이징·서킷브레이커·스윕 기준)

# 안전장치
CA_LIVE_MAX_ORDER_USDT=1000      # 1회 주문 노셔널 한도
CA_LIVE_DAILY_ORDER_LIMIT=60     # rolling 24h 주문 수 한도
CA_LIVE_MAX_LOSS_PCT=0.05        # 일손실 서킷브레이커 → reduce-only 킬스위치
```

UI ControlBar의 **실거래 전환** 버튼(타이핑 확인 모달) 또는 `POST /api/trading-mode {"mode":"live","confirm":"LIVE"}`. 전환 시 키 검증 → 심볼별 isolated·레버리지 설정 → 포지션/주문 리컨실 후에만 활성화되며 헤더가 빨간 live 뱃지로 바뀝니다.

**API 키 권장 설정**: Read + Trade 권한만(출금 권한 불필요 — 봇은 출금 API를 호출하지 않습니다), IP 화이트리스트 등록. 주문 수 한도는 래더 매매 특성상(플랜당 진입 3 + 익절 2 + 재발주) 넉넉히 잡아야 정상 매매가 막히지 않습니다.

## AI(LLM) 기능 — 기획

지금 시스템은 **의도적으로 LLM 없이** 결정론적으로 동작합니다("같은 입력 → 같은 플랜"이 보장돼야 walk-forward 검증과 룩어헤드 오염 테스트가 성립). 이 원칙을 지키면서 LLM을 얹을 수 있는 자리를 다음과 같이 정리했습니다.

### 원칙 — 붙이지 않는 곳

**매매 판단 경로에는 LLM을 두지 않습니다.** 진입/청산 결정, RiskEngine 게이트, PositionMonitor 루프는 결정론 유지가 필수입니다:

- 백테스트 재현성이 깨지면 OOS 검증·오염 테스트가 무의미해짐
- LLM 호출 지연(수 초)이 5초 리스크 루프에 들어가면 손절·청산 감시가 늦어짐
- 규칙 강제(RiskEngine)는 감사 가능해야 함 — 확률적 판단이 개입할 수 없음

### 붙일 곳 (검증 경로 밖, 읽기 전용)

| 순위 | 기능 | 설명 | 매매 영향 |
|---|---|---|---|
| **1** ✅ | **리포트 해설** (구현됨) | 사이클 리포트의 숫자 표에 자연어 요약을 덧붙임 (승/패 패턴, 손실 성격, 레짐 변화 시 예상 영향) | 없음 |
| **2** | **로그·상태 자연어 질의** | "어제 ETH는 왜 진입 안 했어?" → 로그·플랜·거부 사유를 조회해 답변 | 없음 |
| 3 | 전략 아이디어 → 템플릿 초안 | 가이드 문서의 미구현 전략을 코드 초안으로 생성. 이후 **사람 리뷰 + 백테스트/OOS 검증 통과** 후에만 실전 편입 | 간접(검증 경유) |
| 4 | 파라미터 탐색 가이드 | 과거 결과를 읽고 다음 탐색 방향 제안 (현재 랜덤+±20% 변이 대체) | 간접(검증 경유) |
| 5 | 이벤트 캘린더 자동 채움 | CPI·FOMC 블랙아웃용 `econ_events` 자동 입력. 오입력 시 매매 차단/노출 위험이라 **사람 확인 필수** | 직접(주의) |

### 설계 제약

- **선택 기능(opt-in)** — API 키가 없으면 LLM 계층 전체가 비활성화되고 기존 리포트·UI가 그대로 동작. 오프라인·키 프리라는 현재 장점을 잃지 않음
- **읽기 전용** — LLM은 DB·로그를 읽기만 하고 주문·설정·플랜을 변경하지 않음
- **숫자는 코드가 계산** — LLM은 이미 계산된 값을 서술만 함 (수치 환각 방지)
- **실패 무해** — LLM 호출이 실패/타임아웃되면 해당 섹션만 생략하고 사이클은 정상 완료

**구현 순서**: 1(리포트 해설) ✅ → 2(자연어 질의) → 그 외는 실사용 후 판단.

### 리포트 해설 — 사용법

기본값은 **꺼짐**입니다. 키를 넣지 않으면 `backend/app/llm/`는 로드만 되고 아무 동작도 하지 않으며, 리포트 마크다운은 이전과 **바이트 단위로 동일**합니다(회귀 테스트로 고정).

```bash
# 1. 선택 의존성 설치 (설치 안 해도 시스템은 그대로 동작 — 해설만 생략)
pip install -r backend/requirements-llm.txt

# 2. backend/.env 에 추가
CA_LLM_ENABLED=true
CA_ANTHROPIC_API_KEY=sk-ant-...
# 선택: CA_LLM_MODEL=claude-opus-5 / CA_LLM_EFFORT=low / CA_LLM_TIMEOUT_SECONDS=45
```

켜면 전략 발굴·워크포워드 검증 리포트 끝에 `## 🤖 AI 해설` 섹션이 붙습니다.

| 구성요소 | 역할 |
|---|---|
| `backend/app/llm/client.py` | Anthropic SDK 래퍼. 비활성·SDK 미설치·타임아웃·API 오류·거부·빈 응답을 전부 `None`으로 흡수 — **예외를 밖으로 던지지 않음** |
| `backend/app/llm/narrator.py` | 이미 계산된 지표만 담은 프롬프트를 만들고 해설 섹션 마크다운을 반환 |
| `backend/app/agents/analyst.py` | 결정론 리포트 생성 후 해설을 **덧붙이기만** 함. 실패 시 경고 로그만 남기고 리포트는 그대로 저장 |

시스템 프롬프트가 "주어진 수치만 인용, 새 숫자 계산 금지, 투자 권유 금지"를 강제하고, 섹션 하단에 "매매 판단에 사용되지 않음" 고지가 자동으로 붙습니다. `GET /api/config`의 `llm` 필드로 활성 여부와 모델명을 확인할 수 있습니다(키 값은 노출하지 않음).

## 실전 운영에서 잡은 버그들

실계좌 운영 중 발견·수정한 것들입니다. 같은 계열 결함을 멀티에이전트 감사로 함께 훑어 총 **19건을 일괄 수정**했고, 모두 회귀 테스트가 붙어 있습니다.

### 자금 안전 관련 (critical)

| 증상 | 원인 | 수정 |
|---|---|---|
| 손절된 플랜의 복구 로직이 **새 포지션을 5초마다 청산 시도** | 심볼 재진입 시 옛 stopped 플랜이 현 포지션을 자기 것으로 오인 (reduce-only 수량 초과로 거부돼 실피해는 없었음) | 포지션 소유권 가드 — 더 새로운 플랜이 있으면 복구 스킵, side 매칭 필수 |
| 라이브 강제 청산이 **'익절'로 오분류**되고 내역에서 사라짐 | 청산 감지가 페이퍼 전용 문자열에 의존 | 봇 청산 체결 없이 포지션 소멸 시 '청산 의심' 처리 |
| 헤지 모드에서 **수동 반대 포지션 오청산 위험** | 포지션 조회가 심볼만으로 키잉 | 모든 조회를 (심볼, 방향)으로 키잉 |
| 모호한 발주 실패 시 **주문 유실/중복** | 조회 실패를 '거부'로 단정 | pending-unknown 미러 후 settle이 clOrdId로 해소 |

### 매매 중단 유발 (운영 장애)

| 증상 | 원인 | 수정 |
|---|---|---|
| **모든 trade 사이클 실패**, 신규 진입 전면 중단 | 출금 스윕이 `now_ms=None`을 처리 못 해 TypeError | None이면 현재 시각 사용 |
| 특정 심볼이 **24시간 진입 차단** | 거래소가 래더를 전량 취소했는데 플랜이 `approved`로 고착 | 래더 소멸 시 즉시 abandoned 처리 |
| 주문 예산 소진으로 **전 심볼 발주 거부** | GTX 크로싱 즉시만료가 재큐 루프를 유발 + 24h 한도 20건이 래더 매매에 부족 | rejected 미러로 루프 차단 + 한도 60으로 상향 |
| OKX 실거래 전환 실패 (400) | 양방향 계정은 격리 레버리지 설정에 `posSide` 필수 | 계정 posMode 감지 후 방향별 설정 |
| **체결이 전혀 안 됨** (페이퍼) | 설정 TF에 1m이 없어 체결 판정용 봉을 아무도 수집하지 않음 | settle이 1m 봉을 직접 최신화 |

### 데이터 정확성

- **부분 체결 래더의 청산 버퍼** — 가중 평균이 아닌 **최악 케이스 레그** 기준으로 심사 (하위 레그 미체결 시 청산가가 손절선 위로 올라오는 문제)
- **펀딩 지터** — 실데이터 `fundingTime`의 ms 오차로 정산이 누락되던 것을 봉 귀속 방식으로 변경
- **진입 봉 청산 미검사** — 같은 봉에서 진입 후 청산가까지 스윕되는 경우를 놓치던 백테스트 결함
- **동일 봉 예외적 종가 체결** — 크로싱이므로 taker 요율 적용
- **일손실 서킷브레이커 오작동** — 오늘 첫 스냅샷 기준선이 자정~첫 스냅샷 사이 손실을 누락 → 어제 마지막 스냅샷 기준 + 출금액 되더하기
- **최종 익절 더스트** — stepSize 절사로 잔량이 남아 플랜이 영구 active로 고이던 문제 → 마지막 레그는 잔량 전량 사이징
- **타임스탬프 형식 혼용** — `'T'` 구분자 vs SQLite 공백 형식의 바이트 비교 오류 전수 정규화
